## 1. 背景与需求

### 1.1 当前项目状态

项目已实现基于 AutoGen + MCP 工具的搜索 Agent，使用 `jina_search`、`jina_reader`、`fetch` 等工具执行网页搜索和内容读取任务。现需批量产出 Agent 轨迹，用于构造 Judge 微调数据。

### 1.2 核心需求

- **下载现成数据集**：从开源社区获取已有的搜索 Agent 轨迹数据
- **自生成补充数据**：基于现有 MCP 工具链生成特定场景轨迹
- **Judge 数据构造**：将轨迹转化为偏好对/评分标注数据

### 1.3 数据集筛选标准

| 维度 | 要求 |
|------|------|
| 场景匹配 | 搜索+读取类工具调用轨迹 |
| 轨迹完整性 | 包含完整的工具调用链（query→search→read→answer） |
| 数据格式 | 含消息序列、工具调用、执行结果 |
| License | 可商用或学术可用 |
| 规模 | 至少数千条有效轨迹 |

### 2.2 OpenSeeker-v1（高质量搜索轨迹）

| 属性 | 详情 |
|------|------|
| **来源** | 上海交通大学，arXiv:2603.15594，2026 |
| **规模** | 11,700 条搜索轨迹 |
| **License** | MIT |
| **HuggingFace** | `OpenSeeker/OpenSeeker-v1-Data` |
| **GitHub** | https://github.com/rui-ye/OpenSeeker |
| **模型** | `OpenSeeker/OpenSeeker-v1-30B-SFT` |

**核心创新：**

1. **基于知识图谱的 QA 合成**
   - 通过维基百科图谱多跳游走生成复杂推理问题
   - 实体混淆（Entity Obfuscation）抑制单步检索捷径
   - 生成的问题具有可控覆盖范围和复杂度

2. **去噪轨迹合成（Denoised Trajectory Synthesis）**
   - 引入"裁判模型"倒序评估每步动作的信息增益
   - 物理剔除试错、广告、404 等无效步骤
   - 输出极简高效黄金路径
   - 回顾性摘要机制（Retrospective Summarization）

**性能表现：**

- 仅用 11.7K 样本 + 单次 SFT 训练
- BrowseComp：29.5%（超过 DeepDive 15.3%）
- BrowseComp-ZH：48.4%（超过通义 DeepResearch 46.7%）
- xbench-DeepSearch、WideSearch 均达 SOTA

**与项目匹配度：⭐⭐⭐⭐⭐**

## 3. 通用工具调用数据集

### 3.1 Toucan-1.5M（MCP 工具调用轨迹）

| 属性 | 详情 |
|------|------|
| **来源** | IBM + University of Washington，arXiv:2510.01179，2025 |
| **规模** | 1,527,259 条轨迹 |
| **工具数** | 2,000+ 工具，500 MCP 服务器 |
| **License** | Apache 2.0 |
| **HuggingFace** | `Agent-Ark/Toucan-1.5M` |
| **GitHub** | https://github.com/TheAgentArk/Toucan |

**数据格式：**

每条记录包含：
- `messages`：消息序列（system/user/assistant/tool）
- `tools`：工具定义列表
- `tool_calls`：函数调用（name + arguments）
- 分类标注：单步(S)/并行(P)/多步(MS)/无关(IR)

**工具调用场景分布：**

| 场景 | 说明 |
|------|------|
| Single (S) | 单步调用 |
| Parallel (P) | 并行多工具调用（~20%） |
| Multi-Step (MS) | 多步串行调用 |
| Irrelevance (IR) | 不需要工具的边缘情况 |

**构造流程：**

```
1. MCP 服务器元数据收集（GitHub + Smithery.ai）
2. 过滤返回错误的服务
3. 5 个开源 LLM 生成任务场景
4. 3 个模型 + 2 个框架构建步骤级轨迹
5. 2 个 LLM 评分（难度+质量）
6. 规则+模型验证筛选
```

**与项目匹配度：⭐⭐⭐⭐⭐**（MCP 架构完全一致，但非专门搜索场景）

### 6.4 Judge 标注构造

**正负样本对来源：**

| 方法 | 数量 | 说明 |

os.makedirs(output_dir, exist_ok=True)

# ========== 第一梯队：直接可用 ==========

# 1. MiroVerse（最大搜索轨迹数据集，147K+）

    miro[split].to_json(f"{output_dir}/miroverse_{split}.jsonl")

# ========== 第二梯队：补充参考 ==========

### 7.4 使用 huggingface-cli 下载

```bash
# 下载到指定目录
huggingface-cli download --repo-type dataset \
  --token YOUR_HF_TOKEN \
  miromind-ai/MiroVerse-v0.1 \
  --local-dir ./data/MiroVerse-v0.1 \
  --resume-download

huggingface-cli download --repo-type dataset \
  --token YOUR_HF_TOKEN \
  OpenSeeker/OpenSeeker-v1-Data \
  --local-dir ./data/OpenSeeker-v1 \
  --resume-download

huggingface-cli download --repo-type dataset \
  --token YOUR_HF_TOKEN \
  Agent-Ark/Toucan-1.5M \
  --local-dir ./data/Toucan-1.5M \
  --resume-download
```
